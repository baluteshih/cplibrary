# 三維凸包的支撐平面：出題備註

作者專用；題面見 [statement.md](statement.md)。目標為 [Geometry/convexHull3D.hpp](../../../../Geometry/convexHull3D.hpp)，並涉及 [Geometry/Point3D.hpp](../../../../Geometry/Point3D.hpp) 的精確乘積運算。

## 覆蓋對應與前置條件

| 介面／資料 | 可觀察結果 |
|---|---|
| 建構子 | 從任意起始排列找出三維凸包，忽略重複、內部與非頂點的邊界點 |
| P、res、Face::a/b/c | 從回傳三角面恢復正確的外向支撐平面 |
| same | 同一平面上的三角面應屬同一幾何面 |
| polygon_face_num | F 是 maximal planar facet 數，不是三角面數 |
| get_volume | V_6 為正的六倍真實體積，不能再除六或取任意符號 |

題目只能驗證可觀察結果，無法強迫 driver 使用 same 或 polygon_face_num，而不是自行對支撐平面去重。但輸出 F 與完整平面集合能檢查這些 API 的數學語意。

點集保證 affine dimension = 3，符合 header 明示排除所有點共平面的限制。允許重複點、前三點共線、前四點共平面、面內與邊上點；不能為了讓初始化或共平面處理容易而偷偷改成「任四點不共平面」。不涵蓋空輸入、點／線／平面凸包或浮點 eps。

建構子會交換自身 P 的前幾個元素，Face 的索引對應建構後的 P，不保證仍對應呼叫前的輸入陣列。這是需要讓使用者學會的 API 細節；題面改輸出幾何平面，避免要求不存在的原始索引保證。

## 型別範圍

座標上限 C = 10^9。差向量用 signed 64-bit 可容納；三點叉積的單一分量可用 8C² 作保守上界，小於 signed 64-bit 上限，但其平方與三維體積乘積需用 __int128。

初始化中的 cross(p, P[0], P[1]) 來自同一個邊長 2C 的立方體內三點。其平方長度的最大值為 48C⁴ = 4.8×10^37：平方長度對每個輸入點分別為凸函數，最大值可取立方體頂點，枚舉三個頂點即得此界。因此 MulT = __int128 可以容納此處運算，不能以三個互相獨立的分量最壞值誤認一定溢位。

Primitive 法向量可存 signed 64-bit；d 與 V_6 需要更寬的整數。V_6 ≤ 6(2C)³ = 48C³ = 4.8×10^28。參考解與 checker 所有乘法均須在運算前加寬；若實作額外的高次比較，要重新分析或使用多精度整數，不能假設所有組合都自動可放進 __int128。

## 獨立參考方案

採逐面探索的 3D gift wrapping，使用精確整數方向／體積判斷；直接維護 maximal polygonal facets，不複製目標逐點刪除可見三角面的增量法。

1. 用投影凸包找到 exposed supporting plane／edge，取得一個初始支撐面。
2. 每個支撐面收集全部共面輸入點，投影至法向量非零分量所對應的二維座標平面，求嚴格 2D 凸包，移除重複及共線中間點。
3. 沿每條面邊 pivot，掃描輸入點取得另一側相鄰支撐面；以 primitive 外向平面去重，直到所有面探索完畢。
4. 每個面可任選扇形三角化，以有向四面體和計算 V_6。保持外向方向，總和自動處理原點位於外部時的負貢獻。

保守規劃時間 O(n² log n)，n ≤ 3 000。實作時先去除重複座標，面內共面點處理完即可釋放；避免另存 n×n 的參考解資料表，或為每個面永久複製所有輸入點。平面與面內頂點排序都必須精確；共面時一次處理整個面，不能把不同三角化當不同答案。建立 package 時須先實測最大案例的時間與峰值記憶體，不把這個保守複雜度標記當作一定能在時限內完成的保證。

此參考方案較一般 2D 凸包複雜；建包前依使用者批准採用，實作時若 pivot 的退化處理無法可靠收斂，提出具體反例與使用者討論，不無限制自行推導。不能改用被測 header 或新 general 半平面交版本作答案來源。

小例另用 O(n⁴) 獨立支撐平面枚舉核對：每三個非共線點構成候選平面，檢查所有點在單側，正規化並去重；將每面的共面點投影做 2D 凸包後計算體積。僅用在小 n，不拿此法硬做正式最大案例。另以四面體、盒子、稜柱及棱錐的解析面數／體積核對大案例。

## 二次複雜度的壓力設計

日常 CI 採 n ≤ 3 000、時限 3 秒、記憶體 512 MiB。原模板明確配置 n×n 的 flag；以 4-byte int 計算，最大資料需要 36,000,000 bytes（約 34.33 MiB），另計 row 容器、點與面的資料。10 000 點的大壓測不放進本 package，也不加入自動 CI 流程。

有限測試不能證明漸近複雜度，目標是排除明顯超過二次的行為，並保留能在使用者 driver 完成後觀察成長率的資料：

- 同一個 50×60 整數格點族，P(x,y) = (x,y,x²+y²)，取巢狀的 n = 500、1 000、2 000、3 000 個點。每個點都有唯一切平面，因此全部都是凸包頂點，且其任意子集仍保有這個性質。每個足夠大的前綴的面數也是 Θ(n)，避免用少量外殼包住大量內部點，讓逐面掃描只做近線性工作。
- 上述格點含很多共平面的四點，另外加入 P(x,y) = (x,y,M(x²+y²)+e_xy)，M = 10 000、|e_xy| ≤ 1 000 的擾動族。對任意其他整數格點，切平面判斷的高度差至少 M − 2 000 > 0，因此每個點仍為凸包頂點；擾動可減少規則格點的平面合併，不能用不受控的浮點球面取整宣稱所有點仍在凸包上。
- 幾何順序與固定種子打亂順序分配在不同的分級案例；另保留較小的長共平面前綴、棱錐／稜柱及大量內部點案例，分辨一般位置效能、退化處理與初始化成本。合法整體平移到接近 10^9 的座標亦須保留，並確認所有輸出／中間乘積仍在範圍內。
- 最大 n = 3 000 的檔案至多兩筆，其餘壓力資料使用分級規模；維持總檔案數約 20，不用重複很多最大案例堆時間。
- 準備正確但 O(n³) 的逐面／逐邊額外全掃描錯解作效能對照；只有實際在壓力資料穩定 TLE 才宣告預期 TLE，不能拿支撐平面枚舉的 O(n⁴) 被擋下，冒充已驗證二次與三次的差異。

建構子與 polygon_face_num 都可能花 O(n²)；後者會成對比較 res 的三角面。題目總執行時間無法自行區分這兩階段。使用者完成 driver 並另行要求量測時，應分別記錄建構、polygon_face_num、平面正規化與輸出成本，再看 2 倍點數的時間是否接近 4 倍，以及 time/n² 的趨勢。不能只根據單一最大資料 AC 就宣稱已證明建構子為 O(n²)，也不強迫 driver 加入計時輸出。

## 測資、錯解與 checker

必測：重複點起始、長共線前綴、長共平面前綴、內部點很多、所有點都在凸包上、立方體／稜柱的非三角形面、面內與邊上大量點、原點在內／外／面上、整體平移、輸入排列變化、接近共平面但有非零體積、大座標。

需要針對 get_volume 的因子六、三角面數冒充真正面數、法向量方向反轉、d 符號錯誤、平面未約分／排序、重複面、漏掉共平面面片、先假設前四點構成四面體、64-bit 體積或初始化叉積平方溢位、僅對一般位置正確等錯解設計反例。

Custom exact checker：解析到可容納 d、V_6 的整數型別，拒絕多餘／不足 token，確認 F、V_6、primitive 法向量、平面集合、外向符號與字典序全數正確。不接受只翻轉方程符號的「等價平面」，也不依賴選手提供三角剖分。面數上界可用 2n − 4 作保守驗證界。

Validator：檢查 n、座標、EOF 與 affine dimension = 3，允許重複點；用獨立精確線性獨立判斷確認維度，不引用目標 library。

## 預算與狀態

規劃約 20 筆，輸入加答案合計不超過 8 MiB，3 秒、512 MiB，筆數 × 時限約 60 秒；參考解加約 7 份錯解的完整基礎額度約 480 秒，這是各筆全部耗盡時限的上限估算，不是實際時間目標。大多數資料為小型正確性案例，n = 3 000 至多兩筆；以兩筆最大案例均耗盡時限估算，它們占使用者單份 driver 約 6 秒的時限額度。建立 package 時必須記錄生成、參考解與完整 roster 的實際時間；若 CI 成本仍高，先替換／裁剪重複壓力資料或優化獨立參考解，再與使用者討論必要調整，不偷偷刪除退化覆蓋或放寬時限。
