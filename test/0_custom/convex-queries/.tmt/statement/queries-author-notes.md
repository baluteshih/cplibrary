# 凸包上的定位與支撐線的出題備註

本文件供建立 package 與測試 driver 的 agent 使用，不屬於選手題面。正式敘述在 [queries.md](queries.md)；本題是獨立 batch 題，不需要互動或 grader。

## 驗證目標與前置條件

目標 header 是 [Geometry/convex.hpp](../../../Geometry/convex.hpp)，主要驗證 `pointInConvex`、`tangentDirection`、`tangentLineToConvex`。

凸包非空。n = 1、2 時只有 I／D 查詢；T 查詢只出現在 n ≥ 3，且查詢點嚴格位於凸包外。輸入的非退化凸包必須逆時針、沒有重複頂點及連續共線頂點。Validator 也應排除自交與多重繞行，不能只檢查每個局部轉向；可獨立重建凸包後核對循環序列。

小規模用全頂點／邊掃描核對，大規模須使用高效率參考解。方向極值及切線樣例只是一組合法輸出，不能將任意一個參考編號視為唯一答案。

所有輸入座標的絕對值不超過 10^8。差向量與乘法應使用足夠寬的型別，不能先以 32 位整數計算再轉成 64 位。使用獨立參考實作，不以被測 header 當唯一 oracle。

## 實作與測資細節

`pointInConvex` 的回傳值對照為 `1 → IN`、`0 → ON`、`−1 → OUT`。單點／線段案例主要用於此函式和方向極值，不提供切線查詢。

`tangentDirection(d,C)` 最大化的是 `cross(d,C_i)`，不是最大化 `dot(d,C_i)`；方向差一個直角會得到另一個支撐點。題面使用原始叉積定義，避免偷換成一般點積極值。

`tangentLineToConvex(P,C)` 的兩個回傳位置須依題面固定順序檢查：第一條 P → C_a 的其餘頂點全在左側或線上，第二條 P → C_b 的其餘頂點全在右側或線上。**不可接受將兩者交換，也不可在 checker 中先排序這兩個編號。** 支撐線沿整條邊時可接受該邊任一端點，但不能因此放寬兩條切線的順序。

大測資的 checker 不應對每個候選編號掃完整個凸包。可由獨立參考解預先求每條切線／方向極值的合法頂點集合：嚴格凸多邊形上每條支撐線最多含相鄰的兩個頂點，再做常數時間的 membership 檢查。小資料才用全頂點叉積核對。需由參考資料完整列出 ties，不能只把某一個任意合法編號當唯一答案。

測試頂點循環位移（不能總讓編號 0 是最左點）、長度很不平均的邊、軸向及斜向支撐線、方向相反、極值為整條邊、外點在邊的延長線、非常靠近頂點的合法外點、±π 附近的方向。以大 q 攔截每筆全掃的實作，也應保留 n = 1、2 的合法 I／D 查詢。

## 測資成本與交付

先以約 20–40 份有辨識力的資料規劃，不將隨機測資膨脹到數百份。40 份、每份 5 秒的基礎單次序列時間額度為 200 秒，另需考慮驗證解與唬爛解數量。量測實際資料大小及參考解速度後再校準資源限制。

保留退化情況、邊界規則的反例、小型可暴力核對資料及少量上界資料。離線可大量測試變形，但正式資料只保留可區分錯解的代表。

交付本題的 statement、validator、reference、必要 checker、測資與錯解證據。若目標函式無法編譯或違反題面語意，保留最小反例並回報，不應偷偷放寬題目讓它通過。

可做凸包循環位移、平移、反射及交換座標。需要同步更新索引和查詢；反射後須恢復逆時針順序，並注意固定的左／右切線順序，不能只沿用原編號。
