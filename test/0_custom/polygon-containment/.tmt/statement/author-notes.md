# 點在輪廓的哪裡的出題備註

本文件為作者專用，題面在 [statement.md](statement.md)。目標是 [Geometry/polygon.hpp](../../../../Geometry/polygon.hpp) 的 `pointInPoly`：預設／strict=false 的邊界包含模式、strict=true 的嚴格模式，以及 `pointStrictlyInPoly`。`.test.cpp` 和 CI 串接保留給使用者；不要代寫轉換這些回傳值的程式。

## 合約與覆蓋

本題三分類可以觀察嚴格內部與包含邊界之間的差異，但不能單靠輸出強迫 driver 同時呼叫 strict=true 與 `pointStrictlyInPoly`；使用者可自行在 driver 核對這兩個等價入口。空集合在此不使用索引方法，頂點迴圈為空；單點與線段只具有邊界。

對 n ≥ 3，禁止自交、洞、重複頂點及重疊／折返邊，允許同方向的連續共線邊。簡單性 validator 應獨立檢查邊相交，不能只檢查相鄰叉積。規劃 n² 的檢查時也要量測 validator 成本；必要時降低正式資料的 n 或使用高效率相交偵測，不能把幾秒 solver 換成數分鐘 validator。

與凸包的點位置不同，此題必須保留凹多邊形，也不要求輸入逆時針。查詢點、頂點與所有叉積可使用精確整數計算；乘法前轉為足夠寬的型別。

## 獨立參考方案

使用獨立實作的 winding number，先作精確邊界判斷，再計算非零繞數；n = 0、1、2 另定義。每個查詢 O(n)，總 O(nq)，空間 O(n)。此方案不 include/copy 被測 header 的奇偶射線實作。

小規模可用合法簡單多邊形的三角剖分作第二種 oracle，或以手算的正交多邊形核對。不要用凸包、包圍盒或浮點角度總和作唯一答案來源。題面 max(1,n) × q 的上限允許被測的線性查詢方式，不要求另做離線查詢資料結構。

## 測資與錯解

- 空集合、單點、斜線段及其端點／延長線，確保 OUT、ON 與 IN 不混淆。
- 一般凸多邊形只占部分案例，主要補凹槽、階梯形、細長走廊與查詢位於凸包內但多邊形外的資料。
- 水平／垂直邊、連續共線頂點；查詢恰在頂點、邊中間、共線延長線，以及和多個頂點同高但不在邊上的點。
- 射線通過頂點時的局部極大／極小，以及重複計數相鄰邊的反例。
- 同一組多邊形／查詢反轉頂點順序後答案不變；平移、反射與交換 x/y 也應保持三分類。
- 錯解包括邊界當內部、strict=false 仍排除邊界、用凸包代替原多邊形、每次頂點穿越算兩次、水平邊除零、只支援逆時針、32 位叉積、把線段延長線也當 ON。

## Checker 與預算

使用精確字串 token 比對。三分類固定，不需 custom checker 或浮點容許誤差。

規劃約 28 份、原始資料合計不超過 64 MiB，總基礎序列時間額度約 28 × 3 = 84 秒。每份 max(1,n) × q 都要由 validator 驗證；保留少量上界案例和精準的頂點／邊界反例，避免用數百個隨機點雲偽裝成合法簡單多邊形。資料檔數與 validator 實測時間均需回報。
