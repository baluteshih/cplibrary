# 凸包與邊界巡遊的出題備註

本文件供建立 package 與測試 driver 的 agent 使用，不屬於選手題面。正式敘述在 [hulls.md](hulls.md)；本題是獨立 batch 題，不需要互動或 grader。

## 驗證目標與前置條件

目標 header 是 [Geometry/convex.hpp](../../../Geometry/convex.hpp)，主要驗證 `convexHull`、`convexHullNonstrict`、`convexHullParts`。

本題允許空點集，四個輸出區塊使用固定順序及起點，應精確比對。小規模可窮舉支撐邊交叉驗證；大規模使用獨立高效率凸包解法。

所有輸入座標的絕對值不超過 10^8。差向量與乘法應使用足夠寬的型別，不能先以 32 位整數計算再轉成 64 位。使用獨立參考實作，不以被測 header 當唯一 oracle。

## 實作與測資細節

四個輸出區塊的順序與起點皆固定。嚴格凸包不留邊上中間點；邊界巡遊保留它們。上下鏈都由字典序最小點走向最大點，因此上鏈和凸包逆時針走訪中的上半段方向不同。

全共線的邊界巡遊特意保留「去程和回程」中的中間點，對應 `convexHullNonstrict` 在 header 註解中說明的行為；不要擅自把答案去重成一條單向線段。原始輸入的重複位置則須先去重，兩者是不同情況。

保留空集合、全重複、兩點、垂直／負斜率共線點、矩形各邊密集共線點、重複的極值點、大量內部點、幾乎所有點都在凸包上的案例。至少區分「把上下鏈弄反」「嚴格／非嚴格的叉積比較寫反」「漏掉首尾點」「全共線回程處理錯誤」。

Driver 可另對已排序且去重的同一組點呼叫 `sort_and_unique=false`，與預設版本比對，以涵蓋三個函式的旗標路徑。不要將尚未排序或含重複的原始資料傳入此模式，再將前置條件違反誤報為 library 錯誤。

## 測資成本與交付

先以約 20–40 份有辨識力的資料規劃，不將隨機測資膨脹到數百份。40 份、每份 5 秒的基礎單次序列時間額度為 200 秒，另需考慮驗證解與唬爛解數量。量測實際資料大小及參考解速度後再校準資源限制。

保留退化情況、邊界規則的反例、小型可暴力核對資料及少量上界資料。離線可大量測試變形，但正式資料只保留可區分錯解的代表。

交付本題的 statement、validator、reference、必要 checker、測資與錯解證據。若目標函式無法編譯或違反題面語意，保留最小反例並回報，不應偷偷放寬題目讓它通過。

可對原始點雲重排、平移、反射及交換座標；變形後重新規範化輸出，尤其注意上下鏈與逆時針順序。
