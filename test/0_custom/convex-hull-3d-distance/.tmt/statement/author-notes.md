# 凸包支撐平面的距離：出題備註

作者專用；題面見 [statement.md](statement.md)。目標為 [Geometry/convexHull3D.hpp](../../../../Geometry/convexHull3D.hpp) 的建構結果 P、res，以及 `get_dis<Ret>(Point, Face)`。與精確體積／平面集合題分開，讓浮點容許誤差與精確整數輸出不混在同一 checker。

## 覆蓋與 driver 合約

輸入 v 是某個真正 maximal facet 的 primitive 外向法向量。凸多面體中，相同外向方向只有一個支撐面；該面可被任意三角化，因此 driver 可以選 res 中任何位於此平面的非退化 Face，距離都應相同。這不要求 Face::a/b/c 的特定順序或特定三角剖分。

建構子會重排自身 P；Face 索引對應建構後的 P。使用者須自行建立法向量至面的對應，不提供程式碼或 adapter。查詢可在平面兩側、平面上、面多邊形外，驗證 get_dis 的絕對值與無限平面語意，不是點到有限三角形的距離。

保證點集三維，允許重複點、起始共線／共平面，以及面／邊上的非頂點輸入。全部共平面等非三維凸包、零面積 Face、浮點 eps 模式不在本題的有效輸入範圍。

## 獨立參考解與 Validator

不需要建立 3D 凸包：對每個不同的查詢法向量 v，直接掃描全部 n 點，求 d = max dot(v,P)。答案為：

```text
abs(dot(v,Q) − d) / sqrt(dot(v,v))
```

分子與平方長度先精確用 __int128 計算，再轉成 long double 做最後的平方根與除法，避免在大座標平移下先用浮點相減。向量分量上限 8×10^12、點座標 10^6，所有這些乘積均可由 __int128 容納。

以 primitive 整數向量快取 d。若不同法向量數為 D，時間 O(nD + q log D)、空間 O(n + D)，可串流讀查詢。每個有效法向量對應不同的真正面，因此 D ≤ F ≤ 2n − 4。相對於目標先建凸包再查表，參考解用直接最大內積提供獨立答案來源。

Validator 對每個不同 v 另外收集達到最大內積的輸入點，確認至少有三個不同且不共線的點。只接觸邊或頂點的方向必須拒絕；不能僅檢查 v 非零。檢查 n、q、座標、向量上限、primitive、點集維度及 EOF，重複點仍合法。驗證成本亦為 O(nD + q log D)。

小例以 Python 整數／高精度 Decimal 核對平方根與距離；盒子、四面體與平移／旋轉坐標軸的同構案例有解析答案。所有範例已依平面方程手工核對。

## 浮點界限與測資

本題的點座標上限刻意為 10^6，避免把 10^9 平移下的浮點相消與第一題的精確整數範圍混為一談。仍包含法向量很大、分子大、距離為零或非常接近零的案例。容許誤差為 10^(-8) × max(1,正解)，package 建立時以高精度 oracle 量測誤差，不能為了讓任一 driver 通過而事後放寬。

資料需涵蓋：立方體／稜柱同一平面的不同三角面、任意初始排列、重複／內部／邊界點、原點不在凸包內、Q 在平面兩側與平面上、垂足在面外、很大 primitive 法向量、面數多且查詢交錯、單一方向大量重複，以及混合多種方向。

錯解至少包括：漏絕對值、漏除法向量長度、除平方長度、距離到有限三角形／多邊形、法向量約分後 d 未同步、方向反轉但使用另一個支撐面、使用原輸入陣列解讀重排後 Face、32／64 位分子溢位、float 或不穩定數值計算。O(nq) 每筆重掃可能另作效能錯解，但必須實測能在合理測資下穩定 TLE 才宣告，不以預期代替證據。

Custom numeric checker 逐筆檢查非負、有限數、誤差以及 q 個 token 恰好；測試缺輸出、多輸出、NaN／無窮大、負值與正負接近容許誤差邊界。不能只確認最小／最大距離而漏掉個別方向的對應錯誤。

## 預算與狀態

規劃約 24 筆，輸入加答案合計不超過 64 MiB；3 秒、512 MiB，筆數 × 時限約 72 秒。只放少數 q = 200 000 的案例，其他以針對性幾何反例為主。參考解加約 7 份錯解的完整基礎額度約 576 秒，實測後以替換／裁剪控制資料，不增加成數百筆。
